인증 플로우

로그인 방식별 UID 형식

방식처리Firebase UID 형식시점
카카오Cloud Functions(kakaoLogin) → Custom Tokenkakao:{kakaoId}베타
네이버Cloud Functions(naverLogin) → Custom Tokennaver:{naverId}베타
전화번호Cloud Functions(phoneLogin) → Custom Tokenphone:{phone}베타
본인인증verifyIdentity → 신규 유저 등록Firebase 자동 생성베타
AppleFirebase Auth 직접 처리Firebase 자동 생성이후

전체 흐름

1. 소셜 로그인 SDK → accessToken / identityToken 발급
2. 네이버/카카오: Cloud Functions → Custom Token 발급  |  Apple: Firebase Auth 직접
3. FirebaseAuth.signInWithCustomToken() → Firebase UID 발급
4. Firestore users/{uid} 존재 확인
   • 신규 → 본인인증(verifyIdentity) → 프로필 입력 → users/{uid} 생성 → 홈
   • 기존 → 홈

핵심 규칙

  • accessToken 은 매번 달라지나 네이버ID 불변 → 항상 같은 Firebase UID 생성
  • 본인인증은 로그인 방식이 아닌 신원 확인 수단
  • phone 필드로 중복 가입 방지 (같은 전화번호 재가입 불가)
  • isVerified: false 로 초기 생성 → 본인인증 완료 시 true 로 업데이트

Flutter 네이버 로그인 코드 패턴

// 1. 네이버 로그인 → accessToken
final NaverLoginResult result = await FlutterNaverLogin.logIn();
final String accessToken = result.accessToken.token;

// 2. Cloud Functions 호출 → Custom Token
final callable = FirebaseFunctions.instance.httpsCallable('naverLogin');
final response = await callable.call({'accessToken': accessToken});
final String customToken = response.data['customToken'];
final bool isNewUser = response.data['isNewUser'];

// 3. Firebase 로그인
await FirebaseAuth.instance.signInWithCustomToken(customToken);

// 4. 신규/기존 분기
if (isNewUser) { /* 본인인증 화면 */ } else { /* 홈 화면 */ }

자동 트리거 함수

함수명트리거역할
onUserCreatedAuth 신규 유저 생성users/{uid} 문서 자동 생성 (provider, isVerified:false, createdAt). 이미 존재하면 덮어쓰지 않음
onFavoriteCreatedfavorites/{id} 생성clubs.favoriteCount += 1 (FieldValue.increment)
onFavoriteDeletedfavorites/{id} 삭제clubs.favoriteCount -= 1 (0 미만 방지)
onReviewCreatedreviews/{id} 생성ratingSum += rating, reviewCount += 1, rating = ratingSum/reviewCount
onReviewDeletedreviews/{id} 삭제ratingSum -= rating, reviewCount -= 1, count>0 재계산 / 0이면 rating=0
onReviewUpdatedreviews/{id} 수정ratingSum += (new - old), rating = ratingSum/reviewCount
onClubWrittenclubs/{id} 생성·수정name/area/genre/tags → searchTokens(접두사 토큰) 자동 생성. 동일하면 skip(무한루프 방지)

스케줄 함수 — Cloud Scheduler + Pub/Sub (Blaze 필요)

함수명스케줄역할
cleanupPastPerformances매일 KST 04:00종료된 공연 문서 삭제. startAt < now - 8h(PERFORMANCE_DURATION_HOURS)인 공연만 삭제 → 예정·진행 중(새벽) 공연 보존. 500개씩 배치 삭제
공연은 startAt(Timestamp) 후 최대 8시간 진행으로 가정(클럽 마감 ~06:00). 8시간 안 지난 공연은 "진행 중"으로 보존 → 오늘 밤 새벽 공연/어제 이어진 공연 안전. date(YYYYMMDD)가 아닌 startAt 기준 삭제가 핵심. 마감 더 늦으면 PERFORMANCE_DURATION_HOURS 상수만 조정.

구현 시 주의사항

자동 집계 필드 직접 수정 금지 — favoriteCount · ratingSum · reviewCount · rating 은 반드시 Cloud Functions으로만 업데이트.
  • ratingSum / reviewCount 증감은 FieldValue.increment() 사용 (동시 요청 정합성)
  • rating 은 트랜잭션으로 ratingSum / reviewCount 계산 후 저장
  • onReviewDeleted 에서 reviewCount 가 0이 되면 rating = 0 처리
  • deleteUser 는 Admin SDK로만 처리 (클라이언트 직접 삭제 불가)
  • 네이버 UID 형식: naver:{naverId}
  • onUserCreated 는 문서가 이미 존재하면 덮어쓰지 말 것 (중복 실행 방어)
  • onClubWritten 은 searchTokens 갱신이 다시 트리거를 호출 → 기존과 동일하면 즉시 종료(무한루프 방지)
  • cleanupPastPerformances 는 date(YYYYMMDD)가 아닌 startAt(Timestamp) 기준 삭제 — 새벽 공연 오삭제 방지. 스케줄 함수라 Blaze 요금제 필요

클럽 검색 (Firestore 내 — B안)

외부 검색엔진(Algolia) 없이 Firestore만으로 구현. clubs.searchTokens(접두사 토큰 배열)을 onClubWritten 트리거가 자동 생성하고, 앱은 그 배열로 후보를 좁혀 검색한다.

토큰 생성 (functions/src/search/club_tokens.ts)

  • 대상 필드: name · area · genre · tags (소문자화)
  • 각 단어를 접두사로 분해 — 예) "테크노" → 테 / 테크 / 테크노, "어썸레드" → 어 / 어썸 / … → 부분 입력(as-you-type) 매칭 가능
  • 접두사 최대 길이 12, 문서당 토큰 최대 300개
  • 백필 스크립트 scripts/seed_search_tokens.js (기존 클럽 1회 토큰화 — 동일 알고리즘 복제본)

앱 검색 쿼리 (firebase_club_datasource.searchClubsPage)

clubs .where('isActive', isEqualTo: true) // read 규칙(isActive==true) 충족 필수 — 없으면 permission-denied .where('searchTokens', arrayContainsAny: tokens) // 검색어 토큰(최대 10) 매칭 .orderBy('rating', descending: true) // 평점순 정렬 .limit(10) [.startAfterDocument(cursor)] // 서버 페이지네이션 (스크롤 시 다음 10개)
  • 정렬 = 평점순 (관련도 점수 정렬 아님 — Firestore가 점수 정렬 불가, B안 한계)
  • 본 만큼만 read — 10개씩, 스크롤 시 startAfter로 추가. 전체 fetch 안 함
  • 검색어 토큰화: 단어 + 공백제거 통째 (저장 토큰이 접두사라 부분 입력도 매칭)
복합 인덱스 필수 — clubs: isActive(ASC) + searchTokens(CONTAINS) + rating(DESC). firestore.indexes.json에 정의 → firebase deploy --only firestore:indexes. 빌드 완료(Enabled) 전 검색하면 failed-precondition.

환경변수 / 키 관리 (dotenv)

API 키는 .env 파일로 관리하며 절대 git에 커밋하지 않는다. .env.example 은 키 이름만 포함하여 커밋.

Flutter — 프로젝트 루트 .env

KAKAO_NATIVE_APP_KEY=your_key_here     # main.dart: KakaoSdk.init
NAVER_MAP_CLIENT_ID=your_id_here       # main.dart: 네이버 지도 초기화

Cloud Functions — functions/.env

KAKAO_ADMIN_KEY=your_key_here
NAVER_CLIENT_ID=your_id_here
NAVER_CLIENT_SECRET=your_secret_here
main.dart 초기화 순서: dotenv.load → Firebase.initializeApp → KakaoSdk.init → 네이버 지도(NAVER_MAP_CLIENT_ID). 네이버 로그인 secret(NAVER_CLIENT_ID/NAVER_CLIENT_SECRET)은 Cloud Functions 에서만 사용.
