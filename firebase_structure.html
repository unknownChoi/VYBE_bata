전체 흐름

1. 소셜 로그인 SDK → accessToken / identityToken 발급
2. 네이버/카카오: Cloud Functions → Custom Token 발급  |  Apple: Firebase Auth 직접
3. FirebaseAuth.signInWithCustomToken() → Firebase UID 발급
4. Firestore users/{uid} 존재 확인
   • 신규 → 본인인증(verifyIdentity) → 프로필 입력 → users/{uid} 생성 → 홈
   • 기존 → 홈

핵심 규칙

  • accessToken 은 매번 달라지나 네이버ID 불변 → 항상 같은 Firebase UID 생성
  • 본인인증은 로그인 방식이 아닌 신원 확인 수단
  • phone 필드로 중복 가입 방지 (같은 전화번호 재가입 불가)
  • isVerified: false 로 초기 생성 → 본인인증 완료 시 true 로 업데이트

Flutter 네이버 로그인 코드 패턴

// 1. 네이버 로그인 → accessToken
final NaverLoginResult result = await FlutterNaverLogin.logIn();
final String accessToken = result.accessToken.token;

// 2. Cloud Functions 호출 → Custom Token
final callable = FirebaseFunctions.instance.httpsCallable('naverLogin');
final response = await callable.call({'accessToken': accessToken});
final String customToken = response.data['customToken'];
final bool isNewUser = response.data['isNewUser'];

// 3. Firebase 로그인
await FirebaseAuth.instance.signInWithCustomToken(customToken);

// 4. 신규/기존 분기
if (isNewUser) { /* 본인인증 화면 */ } else { /* 홈 화면 */ }

자동 로그인 / 세션 유지 구현 완료

구현 완료 (2026.08.16) — 판정은 core/utils/session_utils.dart(순수 함수) + presentation/auth/viewmodels/session_viewmodel.dart(SessionCheck) 두 곳에만 있다. flutter analyze 경고 0 · 단위 테스트 9건 통과.

현재 상태 — 자동 로그인은 이미 동작한다

Firebase Auth 는 네이티브(Android · iOS)에서 세션을 디스크에 저장하므로 앱을 껐다 켜도 로그인은 이미 유지된다. AuthGate 가 authStateChanges 를 구독해 uid 유무로 진입 화면을 가르는 구조가 이미 있다. 따라서 새로 만들 "자동 로그인 기능"은 없고, 자동 로그인이 상시 켜진 상태에서만 드러나는 구멍을 막는 것이 실제 작업 범위다.

막아야 할 구멍 4가지

#구멍원인 / 근거
1 유령 세션
Firebase 로그인은 됐는데 프로필 미완성		 certification_number_handler.dart 의 finalizeLogin()(세션 성립) → saveUserProfile() 사이에서 앱 종료·네트워크 실패 시 세션만 남는다.
⚠ onUserCreated 트리거가 users/{uid} 를 uid·provider·타임스탬프만으로 먼저 만들기 때문에 문서 존재 여부로는 판별 불가 — 판정 기준은 isVerified
2 isNewUser 오판 naverLogin/kakaoLogin 이 돌려주는 isNewUser 는 Auth user 존재 여부일 뿐 프로필 완성과 무관. 미완성 유저가 재로그인하면 isNewUser=false → 앱이 그대로 홈으로 보낸다
3 죽은 계정 다른 기기에서 탈퇴하거나 Auth user 가 비활성화돼도 로컬 세션은 살아 있다. 자동 로그인이라 재로그인 시점이 없어 영영 감지되지 않을 수 있다
4 소셜 SDK 세션 잔존 signOut() 이 Firebase 세션만 정리한다. 카카오·네이버 SDK 세션이 남아 재로그인 시 계정 전환이 불가능

세션 판정 — 단일 소스

판정은 순수 함수 decideSessionAction()(core/utils/session_utils.dart) 한 곳에만 있다. version_utils.dart 와 같은 패턴.

(또는 users 조회 실패 — fail-open)		MainScaffold
signOut자동 로그인 OFF
또는 isVerified == false · 문서 없음(유령 세션)
또는 토큰 갱신이 서버에서 거부됨		세션 정리 → WelcomeScreen

화면(AuthGate)이 보는 것은 SessionCheck 의 결과 두 가지(ready / signedOut)뿐이다. 검사가 끝나기 전에는 스플래시를 유지한다 — 검사 중 WelcomeScreen 을 잠깐 그리면 멀쩡히 로그인된 사용자에게 로그인 화면이 번쩍인다.

검사는 콜드 스타트 1회 + 복귀 시 토큰만 — 검사가 끝난 뒤로는 AuthGate 가 uid 하나로만 라우팅한다. 앱 실행 중에 프로필 완성 여부를 다시 판정하면, 본인인증(외부 앱·웹뷰) 을 다녀오거나 프로필 저장 직전인 사용자를 로그아웃시킨다. 복귀(resumed) 시에는 서버 무효화 여부만 다시 확인한다.
fail-open 원칙 — users/{uid} 조회 실패·3초 타임아웃은 전부 ready 로 통과시킨다. 오프라인 사용자를 로그인 화면으로 튕기는 쪽이 훨씬 큰 사고다. VersionGate 와 동일한 원칙.
미완성 세션은 가입 재개가 아니라 signOut — 세션을 살린 채 본인인증 화면으로 직행시키면 뒤로가기·중도 이탈 경로를 전부 따로 처리해야 한다. 유령 세션을 즉시 정리하고 Welcome 부터 다시 태우는 쪽이 단순하고 안전하다 (사용자는 소셜 버튼 한 번 더 누르면 본인인증으로 이어짐).

점검 모드isMaintenance=true 는 최신 버전 유저까지 전원 차단한다. 켜기 전에 대상 범위를 확인할 것. 끄면 유저가 '다시 시도' 버튼으로 바로 복귀한다
버전 값 형식"1.2.0" 처럼 숫자·점만. 빌드번호(+7)·프리릴리스(-beta1)를 넣어도 무시되므로 핫픽스도 patch를 올려야 게이트가 구분한다. pubspec.yaml 의 version: 과 스토어 버전명이 일치해야 판정이 맞는다
문서 삭제 금지문서가 없으면 게이트가 항상 통과(fail-open)로 동작해 사실상 꺼진다. 기능을 끄고 싶으면 문서를 지우지 말고 필드를 비운다
storeUrl비어 있으면 Android만 market://details?id={설치된 packageName} 로 폴백한다. iOS는 폴백이 없다 — App Store Connect 등록 후 https://apps.apple.com/kr/app/id{앱ID} 를 반드시 채울 것. 안 채우면 업데이트 버튼이 토스트만 띄운다
오프라인 유저Firestore get() 이 로컬 캐시본을 주거나 3초 타임아웃으로 실패 → 둘 다 통과. 오프라인 상태에서는 강제 업데이트가 걸리지 않는다(의도된 fail-open)
쓰기 권한Custom Claim admin: true 계정만 수정 가능. 어드민 페이지 구축 전까지는 scripts/seed_app_config.js 또는 Firebase 콘솔에서 직접 수정

구현 시 주의사항

자동 집계 필드 직접 수정 금지 — favoriteCount · ratingSum · reviewCount · rating 은 반드시 Cloud Functions으로만 업데이트.
  • ratingSum / reviewCount 증감은 FieldValue.increment() 사용 (동시 요청 정합성)
  • rating 은 트랜잭션으로 ratingSum / reviewCount 계산 후 저장
  • onReviewDeleted 에서 reviewCount 가 0이 되면 rating = 0 처리
  • 네이버 UID 형식: naver:{naverId}
  • onUserCreated 는 문서가 이미 존재하면 덮어쓰지 말 것 (중복 실행 방어)
  • cleanupPastPerformances 는 date(YYYYMMDD)가 아닌 startAt(Timestamp) 기준 삭제 — 새벽 공연 오삭제 방지. 스케줄 함수라 Blaze 요금제 필요
